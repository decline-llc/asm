部署拓扑：代码在 Windows · 工具在 WSL
性能成立前提：工具重 I/O 全留 WSL 原生 fs，跨边界只有命令行与 tar 结果包
Windows 主机 C:\projects\asm\（代码）
· asm/ 编排包：CLI · 8 阶段 + P1/P2 调度
· db.py SQLite 主库（单一事实源）
· panel/ 六引擎 API（httpx 直连）
· browser/ Playwright 小蓝本/爱企查
· 库级能力：dnspython 暴力枚举 · OSINT
· 产出：xlsx 总表+7 sheet · data/ · venv
WSL2 Ubuntu-22.04 ~/asm-ws/（工具）
· bin/ Go 八工具：subfinder dnsx httpx naabu nuclei katana ffuf gowitness
· apt：nmap · masscan · dig · google-chrome（.deb 直装）
· tools/：OneForAll(venv) · a_scan.py · wafw00f
· wordlists/：SecLists（约500MB）
· results/<jobid>/ 原始产出（原生 fs）
bridge.py 桥接协议：wsl.exe 子进程（root 场景 -u root，nmap/masscan 裸套接字）· 超时在 WSL 侧 timeout 强制 · 60s 未完成自动转后台轮询 .done · 数据交换只走管道（stdin→tee 进 / tar→stdout 出），禁 /mnt/c 重 I/O、禁依赖 \\wsl$
边界判定规则：外部二进制 → WSL；库级能力 → Windows 代码内。测试零风险设计：单测全离线 fixtures · 集成用本地假目标服务器（/actuator/env、/.git/HEAD 等 mock）· 半真实仅被动+自有域名
