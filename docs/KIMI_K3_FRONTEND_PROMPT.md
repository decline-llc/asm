# ASM Workbench：前端设计与实现提示词

你是一位擅长安全产品、复杂数据工作台和高质量前端实现的产品设计师兼前端工程师。请为下面的 ASM Workbench 设计并实现一个可运行的前端单页应用。充分发挥你的设计能力，在遵守业务语义的基础上，自主完善布局、组件和交互。直接交付代码与使用说明，不要只提供设计描述。

## 1. 产品背景与目标

ASM Workbench 是一套面向授权安全研究和企业资产治理的互联网暴露面收集框架。用户输入公司名、品牌、根域名和 IP 范围，系统经过种子标准化、股权穿透与 ICP 备案、人工范围确认、子域名收集、DNS/CDN 分析、端口服务发现、Web 识别与截图，最后生成资产报告；还包含 OSINT 和供应链线索模块。

已有后端是 Windows Python 编排、SQLite 数据库和 WSL 工具执行层，入口主要是 CLI。目前没有可供前端直接使用的 REST API、实时事件服务或用户认证服务。

请把前端定位为「以证据为核心的暴露面调查工作台」。让分析人员快速回答四个问题：哪些资产属于这家企业？依据是什么？本轮调查发生了什么变化？下一步应核对什么？围绕公司、域名、IP、服务与证据组织界面。

如能访问仓库，先阅读 README.md、HANDOFF.md、docs/COVERAGE.md、asm/models.py、asm/precision.py 和 asm/stages/s8_report.py；如仅获得本提示词，按这里的上下文直接完成独立演示版。

## 2. 设计概念：让证据有路径

核心体验是一条可探索的调查路径：公司主体 → 域名 → DNS 观测/IP → 端口与服务 → Web 页面 → 证据与复核结论。

但这不是一条默认成立的归属链。关系必须标明「股权」「备案归属」「解析」「服务」「页面观测」等类型；解析到某个 IP 不代表该 IP 的所有服务都属于目标公司。已核实关系、候选关系、异常观测分别用清晰的实线、虚线和状态标签表达。

设计三个特色交互，并让它们真正可用：

- 调查面包屑：从企业进入域名，再打开服务和证据时保留路径，可以回到任意上一级。
- 证据透镜：每条资产能解释从哪里发现、什么时候观测、用了哪些结果、为什么采纳或隔离；重点区分「原始观测」「选用结果」「选择理由」。
- 快照对照：选择两次演示运行，查看新增资产、字段变化和新待核对项；没有可比较数据时展示原因，不绘制虚假的趋势。

## 3. 视觉方向

采用「精密调查仪器 + 企业研究工作台」的气质：安静、清晰、专业，适合长时间看表格与证据。

主内容背景用雾白 #F4F6F8，面板用白色，主文字用墨蓝 #172535，边界用 #E3E8EE，主要操作用青绿 #167D8D。侧栏用深墨蓝。琥珀色表示待复核或数据异常，红色表示错误或已确认高风险，蓝灰表示中性信息。每种状态同时提供文本与图标。

采用紧凑的行高、细线分隔、克制的阴影和 8–12px 圆角。域名、IP、端口、任务 ID 和原始证据使用等宽字体，中文使用清晰的无衬线字体。用统一的线性图标体系。动效以 120–200ms 的抽屉、筛选和状态过渡为主，尊重减少动态效果设置。

视觉重点放在有意义的调查路径、可读的数据表和证据层次。不要用黑客绿代码雨、旋转地球、发光网格、巨型装饰仪表盘、满屏玻璃卡片或无意义的百分比来充当设计。

优先做好 1440px 和 1920px 桌面体验，兼容 1024px 平板与 390px 手机。窄屏侧栏收为菜单，详情抽屉变为全屏，表格横向滚动或切换摘要卡片，筛选条件和关键操作不能消失。

## 4. 应用骨架与首屏

采用单页应用多视图布局：左侧约 220px 导航，顶部约 64px 项目工具栏，其余为主工作区。导航包含项目概览、资产探索、调查任务、证据复核、关系图谱、数据来源、报告中心。环境与配置放在底部。

顶部提供项目切换、全局搜索、最近一次运行时间、「演示数据」状态和新建调查入口。用一条紧凑的上下文条持续展示项目、run_id、采集模式与范围摘要，点击可展开纳入目标和排除项。搜索同时匹配企业、域名、IP、服务标题与任务，支持 Ctrl/Cmd+K、键盘选择和跳转到对应详情。

首屏做成真正能使用的项目概览：

- 显示演示项目「澄川科技集团」、目标范围摘要、当前采集模式和本轮运行状态。
- 四项主指标为可信资产、已收集域名、待核对线索、本轮新增资产，全部由统一数据集计算，并写明统计口径。可信资产按 host + port + proto 去重；域名、IP、服务、URL 不能简单相加成总资产数，同一资产的多个来源也不能重复计数。
- 中部约 2/3 宽度为可点击的公司—域名—服务调查路径，1/3 为「建议优先核对」队列。优先队列写明原因，如来源冲突、发现测试入口、DNS 返回异常地址、截图采集失败。
- 下部显示近期资产变化与最近任务，点击可进入筛选后的资产列表或任务详情。
- 用一条简洁流程展示种子输入、股权/备案、范围确认、子域收集、DNS/CDN、端口服务、Web 识别、报告。股权与备案可作为同一组内的两个子步骤。

用户打开首页，应立即知道当前在调查谁、哪些结果可靠、哪里需要介入。

## 5. 必须做深的四个工作视图

### A. 资产探索

以高质量数据表为核心，提供域名、IP、服务、Web 页面和隔离候选标签页。默认表格展示资产、端口/协议、标题、公司归属、技术栈、CDN 状态、置信度、来源和最近观测时间；其他字段通过列设置或详情查看。

支持组合筛选、排序、分页、列显示设置、复选、多选导出、复制字段和清空筛选。筛选条件包括公司、来源、置信度、端口、服务、CDN、复核状态和资产标签。筛选后展示结果数量，切换视图时保留上下文。

点击一行打开右侧详情抽屉，包含「概况 / 证据 / DNS / Web 与截图 / 相关关系」。抽屉展示来源时间线、DNS 多上游差异、CNAME 链、选用地址及理由、服务指纹、页面证据和原始记录。截图支持放大，并分别显示未采集、文件缺失、采集失败等情况；演示截图可以使用本地生成的页面缩略图并明确标注。

资产主键语义遵循 host + port + proto，同一 host 的不同端口不能误合并；一个域名可以有多个解析地址和历史观测。

### B. 调查任务

提供四步新建调查向导：选择项目和种子 → 确认范围与排除项 → 选择采集模式和阶段 → 查看摘要并创建演示任务。

范围确认同时展示纳入公司、根域名、IP/CIDR、排除 SaaS 和排除理由；股权关系不能自动等价于授权范围。默认被动模式。主动阶段受授权状态和范围配置约束，在相关控件旁简洁解释条件。

任务详情展示阶段流程、工具子任务、耗时、结果数量、失败原因和日志。支持演示任务创建、逐步推进、部分失败、失败项重试和历史查看，所有行为明确属于模拟。暂停或终止等后台尚无可靠能力的操作，可展示禁用状态与原因，不承诺真实控制。

进度按已完成任务数或阶段数表达；总量未知时显示「正在处理」和计数，不能伪造精确剩余时间。P1 OSINT 与 P2 供应链可以拥有独立轨道，但当前实现是顺序执行，不要将真实后端描述为已实现并发调度。

### C. 证据复核

采用「左侧线索队列 + 右侧证据工作台」。覆盖归属待核实、DNS 冲突、假地址、悬空 CNAME 候选、泄露候选、第三方搜索模糊命中和采集失败。

每条线索写清对象、发现方式、观测事实、证据来源、时间、异常原因与建议下一步。允许添加备注、补充演示证据、标记待复核/已复核/排除，并记录操作历史；这些状态变化仅持久化在本地演示数据中。

置信度使用 A/B/C/D/D+/E/F，必须与风险严重程度分开展示，不能把 A 当作高危、F 当作低危。D 级模糊搜索结果属于 assets_quarantine，永不进入可信资产统计或总表；不能设计一键确认就把 D 级候选直接升级为可信资产。重新判断归属应保留新证据并交给后续后端规则处理。

502 响应、指纹命中、悬空 CNAME 或接管候选，都只能显示为待核对线索。域名五类标注「公开 / 有解析未验证 / 内网 / 独立IP段 / 云部署」属于资产分类，也不能包装成风险评分。

### D. 关系图谱

设计局部探索图，而不是一张无法阅读的全量网络。节点包括公司、域名、IP、服务、供应商；按节点类型、关系类型和证据状态筛选，点击节点打开同一个详情抽屉，支持缩放、定位、重置与回到表格。表格、图谱与截图应同步定位选中资产，切换视图不丢失筛选条件和选中对象。

企业节点展示股权比例和层级；服务节点显示端口与技术；候选关系保留证据来源。供应商线索不意味着供应商资产自动纳入目标范围。OSINT 人员信息仅做脱敏演示，避免为了图谱效果堆积个人数据。

## 6. 来源与报告配套视图

数据来源页呈现 FOFA、Quake、Hunter、ZoomEye、Shodan、Censys，以及子域、DNS、Web 工具。区分「工具已安装」「适配器存在」「主流程已接入」「离线已验证」「实网已验证」「未配置凭据」，不能用统一绿灯表示所有能力正常。

当前主流程自动查询以 FOFA/Quake 为主，另四家已有适配器但未全部接入主调度；WSL 的 httpx/gowitness/ffuf/katana 完整接入仍待实现。DNS 可信解析路径有已知待解决问题，需展示异常观测证据与影响，不能预设所有解析已可信。

来源页展示演示调用次数、配置额度、最近错误与结果数量。额度未知显示「未提供」，来源失败和未运行分别显示状态，不要都写成 0。不收集真实密钥、不在浏览器保存真实密钥，配置项仅使用掩码演示值。

报告中心提供「汇报视图 / 工程明细」切换、八张表预览、筛选后 CSV 下载、截图证据查看和打印布局。八表必须对应：总表、equity、domains、ips、urls、systems、social、todos。中文显示名称可以优化，但保留映射。

总表字段保持：序号、资产、端口、标题、技术栈、等级标注、来源、置信度、截图链接。隔离候选不进入总表。已有后端支持 XLSX、八表 CSV 和内嵌 PNG 的独立 HTML；前端未连接后端时，相关下载明确显示待接入，或实际生成并标注「演示数据导出」，不能空点按钮后提示成功。CSV 必须正确处理引号、换行、中文与外部文本公式前缀。

## 7. 演示数据与真实性

构建一个统一、可复现的虚构企业数据集，建议包含 4–6 家关联企业、30–50 个域名、20–30 个服务、8–12 个任务、10–15 条待核对线索，以及两次运行快照。域名用 example.com/example.org 的子域；公网地址示例使用 192.0.2.0/24、198.51.100.0/24、203.0.113.0/24。

至少包含：多来源命中同一域名、同域名多端口、IPv6、CDN 服务、测试环境标签、DNS 上游冲突、198.18.0.0/15 范围内的 fake-IP 异常观测、D 级隔离候选、部分任务失败、截图缺失和未配置来源。fake-IP 只作为异常观测，不成为可扫描的演示资产地址。

所有页面使用同一份数据，指标、表格、图谱和报告可相互核对。区分未发现、未运行、来源失败和字段未知。快照、历史和本地操作记录需要明确标识为演示扩展字段，不把它们冒充现有数据库已经提供的能力。

## 8. 实现要求

仓库已有前端技术栈时遵循现有约定；否则默认 React + TypeScript + Vite，使用适量组件与图表库。将新增前端放入独立 frontend/ 目录，不改动既有 Python 业务、CLI、SQLite 契约、报告生成器和原有设计 HTML。

拆分页面、通用组件、类型、演示数据和服务适配层。所有读取与写入通过可替换的数据服务，不让组件直接绑定演示数组；未来可以在适配层接入后端。区分后端支持、待接入和仅演示能力。

搜索、筛选、排序、抽屉、图谱联动、向导校验、演示复核、模拟任务、实际 CSV 下载和设置持久化必须能操作。每个可点击控件要有可验证结果。任务状态和本地备注可以通过 localStorage 保存，并提供重置演示入口。

不执行真实扫描，不调用第三方 API，不实现前端直接执行 shell，不让用户以为浏览器已连接 WSL。无需创建登录页或权限体系。日志和外部证据按文本安全渲染。

提供加载、空数据、无搜索结果、部分失败、未配置、待接入等状态。支持键盘操作、可见焦点、抽屉焦点管理、Esc 关闭和合理对比度。优先完整打磨概览、资产探索、任务与证据复核，其余视图提供真实可用的核心功能。

## 9. 交付与验收

直接完成可运行前端，给出安装、启动与构建命令，说明演示场景、目录结构和未来需要的接口；后端接口契约只能作为建议文档，不能宣称已经存在。先启动检查核心交互，再运行构建和适用的静态检查，有可用浏览器环境时检查桌面与窄屏布局。

以下演示链路必须贯通：打开概览 → 从待核对项进入 DNS 异常证据 → 查看原始观测与选用结果 → 在资产表筛选所属公司和来源 → 查看 Web 截图状态 → 添加复核备注 → 查看关联关系 → 导出当前可信结果的 CSV。

再验证：新建被动演示任务 → 模拟部分来源失败 → 重试失败项 → 结果计数同步更新；D 级隔离候选始终不出现在可信资产统计和总表中。

最后简洁说明已完成的功能、仍为模拟的能力和关键设计取舍。整体效果应像一套愿意每天使用的专业调查工作台，视觉与交互围绕「归属、证据、变化、行动」四个重点展开。
